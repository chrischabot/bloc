# Notion AI

Notion AI is a suite of integrated features spanning four product surfaces. Each is independently invocable and shares a common chat / completion infrastructure.

## Surfaces

| Surface | Trigger | Purpose |
|---------|---------|---------|
| **Writer** | `Space` in an empty block, or selection + `Ask AI` | Inline drafting, editing, summarising, translating, brainstorming on the current selection or block |
| **AI Block** | `/AI block` | A persistent block whose content is the latest AI completion of a saved prompt; can be re-run |
| **Q & A** | sidebar AI button, `Cmd+Shift+J`, or top-bar Ask AI | Workspace-scoped Q&A; retrieves answers from pages the user can read; cites sources |
| **Agent** | sidebar AI button, full-screen panel | Multi-step agent that can create / edit pages, query databases, schedule work, call connected apps via MCP tools |
| **AI Autofill** | property-level toggle on a database property | When a row is created or its dependencies change, an LLM populates the property from context |
| **AI Meeting Notes** | dedicated `meeting_notes` block / `Cmd+Shift+R` | Capture audio, transcribe, summarise; produces a Meeting Notes page |

## Writer

- Invoked from selection's right-edge floating "Ask AI" pill or by typing `Space` at the start of an empty block.
- Prompt box appears anchored to the block, 480 px wide.
- Quick actions chips:
  - **Summarise**, **Improve writing**, **Fix spelling and grammar**, **Make shorter**, **Make longer**, **Continue writing**, **Translate ▾**, **Change tone ▾**, **Explain**, **Find action items**.
- After completion: actions row (Insert below, Replace selection, Continue writing, Try again, Discard).
- Streaming tokens render with a soft typing animation.
- Cancel via `Esc` while streaming.

## AI Block

- Persistent block: stores `{ prompt: RichText[], output: RichText[], last_run_at, model }`.
- Rendered as a card with `Re-generate` button at top-right.
- Output rendered as rich text; supports the standard annotations + the 19-color palette.
- Cannot recursively reference its own page to avoid infinite expansion.

## Q & A

- Modal centred top of viewport (640 × 600 px).
- Conversation history persists per user, 30-day rolling.
- Each answer: streamed completion + a `Sources` accordion listing the up-to-N referenced pages with title + breadcrumb; click to open.
- Permission check: the model receives only content the asking user has at least `can_read` on.
- "Why this answer?" reveals the retrieved chunks with relevance scores.

## Agent

- Right-side full-height panel (480 px on `≥xl`).
- Tabs: **Chat**, **Tasks**, **History**.
- Chat: streaming responses + tool-call cards (each tool call shows tool name, input summary, output summary, expandable detail).
- Tools available (default toolset):
  - `pages.search`, `pages.create`, `pages.update`, `blocks.append`, `databases.query`, `databases.create_row`, `comments.create`, `users.find`, `web.search`.
- Custom tools: user-defined OpenAPI-described HTTP tools registered in workspace settings.
- Tasks: long-running multi-step plans the agent has accepted; user can pause/resume/cancel.
- History: append-only log of all tool calls (audit trail).

## AI Autofill

- A property option `Auto-fill with AI` on `rich_text`, `select`, `multi_select`, `status`, `number`, `relation`, `people`, `url`, `email`, `phone_number` properties.
- Config: `prompt` (templated with `{{property:<name>}}` placeholders), `trigger` (`on_create | on_demand | when_property_changes`), `model`.
- When triggered, a background job invokes the model with the page's other property values and the body text; result written to the property.
- UI: a small AI badge on the column header; clicking the cell reveals last-run status and a `Re-run` button.

## AI Meeting Notes

- Insert via `/Meeting notes` or `Cmd+Shift+R`.
- Two modes:
  - **Live capture**: requests mic permission, records, transcribes in 30-s rolling chunks.
  - **Upload**: drop an audio/video file (up to 4 hours).
- During capture: a waveform, elapsed time, pause / stop controls.
- After capture: an automatically generated page with sections — **Summary**, **Key points**, **Action items** (auto-extracted, optionally linked to a tasks database), **Decisions**, **Full transcript** (collapsed).
- Speaker diarisation when ≥ 2 speakers; speaker names are editable and remembered per workspace.
- Action items can be linked into a database via a one-time mapping.

## Data model additions

Add tables:

- `ai_runs` — log of every completion (user_id, surface, prompt_hash, model, tokens, cost, latency_ms, created_at).
- `ai_autofill_configs` — per-property config.
- `ai_meeting_recordings` — { id, page_id, storage_key, duration_s, transcript, speakers }.

## API additions

- `POST /v1/ai/completions` — streaming SSE completion endpoint (text / chat). Body: `{ messages, surface, model? }`.
- `POST /v1/ai/qa` — workspace Q&A; permission-filtered retrieval + completion; returns `{ answer, sources: [{page_id, snippet, score}] }`.
- `POST /v1/ai/agent/tasks` — create or continue an agent task.
- `POST /v1/ai/autofill/run` — run autofill for a single row.
- `POST /v1/ai/meeting-notes` — upload audio + page id; returns the page id + job id; subsequent `GET /v1/ai/meeting-notes/{job_id}` polls status.

All under the same Notion-Version header and authorisation model. Each endpoint emits a `ai.<surface>` span and an `ai_run` row.

## Privacy & safety

- Workspace AI-data-retention setting: `off | 30d | 90d` for prompt/response logs.
- Workspace toggle: "Use my workspace data to train models" — defaults to off; never on for any Enterprise plan.
- The AI tier setting (Free / Plus / Business / Enterprise) gates which models are exposed; UI honours plan in the model picker.

## AI Connectors

AI connectors index external content into the workspace embedding store so Q&A and Agent can ground answers across boundaries.

| Connector | Provider | What is indexed |
|-----------|----------|-----------------|
| Slack | Slack OAuth | Channel messages and threads the user can read; updates within 1 hour |
| Google Drive | Google OAuth | Docs, Sheets, Slides, PDFs the user has read access to |
| Microsoft 365 | Microsoft OAuth | OneDrive / SharePoint documents the user can read |
| GitHub | GitHub OAuth | Issues, PRs, READMEs in repos the user can read |
| Linear | Linear OAuth | Issues + comments the user can read |
| Gmail | Google OAuth | Threads the user can read |
| Jira / Confluence / Salesforce / Zendesk | OAuth | Records the user can read |

### Indexing window

Connectors index **up to one year** of prior content per source. Older content is reachable on demand (via a slower, on-the-fly retrieval path) but not embedded. Newer content is incrementally indexed as it arrives (push-based where the provider supports it, polling every 15 minutes otherwise).

### Embedding store

The embedding store is **Turbopuffer** (hosted vector DB). Per workspace + per source:

- One namespace per `(workspace_id, connector_id)`.
- Embeddings produced by the workspace's selected model (`text-embedding-3-large` by default; configurable for Enterprise).
- Metadata: `source_id`, `external_id`, `permission_signature` (hash of the ACL state at index time).
- Retrieval path: query → top-K from Turbopuffer → ACL re-check server-side → completion with the surviving chunks.

### Per-source disable

Workspace admin can disable a connector globally or per-teamspace. User-level "remove this source from AI" lives in Settings → My connections.

## AI Meeting Notes capture (no-bot mechanism)

The system audio path **does not join the meeting as a participant**. Implementation:

- **Browser**: `navigator.mediaDevices.getDisplayMedia({ audio: true })` requesting tab-audio capture; the user selects the meeting tab. Modern browsers (Chromium 110+, Safari 17+) honour `audio: true` on display-media for tab capture.
- **Desktop**: native loopback capture via OS APIs (Core Audio Aggregate Device on macOS, WASAPI loopback on Windows, PulseAudio monitor on Linux). No virtual participant added to the call.
- **Mobile** (iOS / Android): system-audio capture during a meeting is not supported; on mobile the feature falls back to mic-only capture or accepts a screen-recorded video upload.

Latency from speech → transcript chunk available on the page: target ≤ 4 seconds (30-s rolling chunks with overlap).

## Billing (Notion Credits)

- Free / Plus: trial usage with a soft monthly cap; over-cap calls return `402 restricted_resource` with `code: ai_quota_exhausted`.
- Business / Enterprise: bundled allowance per seat per month.
- **Custom Agents** consume **Notion Credits** — a workspace-purchased add-on. Each agent run debits credits based on token usage × model multiplier.
- Credits surface in Settings → Billing → AI Credits with: current balance, monthly burn chart, top-spending agents.
- API: `GET /v1/workspaces/{id}/ai_credits` returns `{ balance, monthly_allowance, used_this_period, period_resets_at }`.

## Observability

- Each AI surface has a span name (`ai.writer`, `ai.qa`, `ai.agent.task`, `ai.autofill`, `ai.meeting_notes`) with `model`, `tokens_in`, `tokens_out`, `latency_ms`, `cost_usd`.
- Failure modes: timeout, content-policy block, retrieval-empty, model-overloaded → logged at `warn` with structured `code`.

## Tests

- Unit: prompt-template renderer; tool-call validator; transcript segmentation.
- Playwright: type `Space` at start of paragraph; assert Writer popover opens; submit a prompt against a stub model; assert streamed tokens render.
- Visual: each AI surface at its primary state.
- Chaos: 100 KB prompts, malformed audio uploads, infinite-loop agent (mocked) — gracefully handled.
- Observability: every AI invocation produces an `ai.*` span and an `ai_runs` row.
